# Access Proof B

A minimal acceptance-test app that demonstrates platform sign-in, shows the signed-in
person their own name and role, and proves two read-only server-side access checks.

Generated by the [Greenlight](https://greenlight.solhann.net) build wizard, and
delivered as a pull request rather than a deploy — a human approving that pull
request is what lets this app exist.

Merging it is also what ships it. A merge to `main` puts this repo live on its own
subdomain automatically, so the approval is the deploy; there is no separate release
step afterwards, and no way to reach production that skips the review.

- **Spec:** [`spec.json`](spec.json) — the capabilities, scopes and tier this app
  declares, agreed with the builder before any code was written.
- **Conventions:** [`AGENT.md`](AGENT.md) — node-free static frontend, PocketBase
  hooks, vendored design system.
- **CI:** every pull request is checked against `spec.json`. Code that contradicts
  its own spec does not merge.

## What it does

- Sign in through the platform identity provider, and sign out again.
- Show the signed-in person their own display name and their role in this app. Both
  come from the record the identity layer writes at login; nothing on the page can
  change either.
- `GET /api/proof/message` — an invented message, returned to any authenticated
  caller. Unauthenticated callers get `401`.
- `GET /api/proof/admin` — a different invented message, returned only when the
  caller's server-set role is `admin`. Ordinary users get `403`, unauthenticated
  callers get `401`.

Both checks happen in `pb_hooks/main.pb.js`, on the server, against `e.auth`. The
page's own buttons stay available whatever your role, so a refusal is something you
can watch happen rather than something you have to take on trust.

There are no app collections, no writes, no outbound calls and no scheduled jobs.
All message content is invented.

## Running it locally

```bash
GREENLIGHT_IDENTITY_MODE=local pocketbase serve --publicDir . --hooksDir ./pb_hooks \
  --dir ./.pb_data --migrationsDir ./pb_migrations
```

Then open http://127.0.0.1:8090.

The identity mode has to be stated explicitly — missing OIDC credentials never choose
a mode for you. In `local` mode the identity hook skips provider configuration and
leaves password auth enabled, so you can make a local account and work. On prod the
mode is `production`: provisioning writes the app's OIDC configuration before the
instance is ever started, password auth is switched off, and the only way in is a
grant.
